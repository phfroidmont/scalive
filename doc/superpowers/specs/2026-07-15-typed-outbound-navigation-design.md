# Typed Outbound Navigation Design

## Purpose

Make outbound navigation as type-safe as inbound routing by deriving locations from the same route declaration used to decode incoming URLs.

Before this change, route paths and parameters used typed codecs while links, patches, navigation effects, and redirects accepted unchecked strings. This allowed a route declaration and its callers to drift apart during refactors. The implemented API makes named route-builder values the source of truth for both directions.

Status: Implemented. The signatures and capability names below reflect the compiled API.

## Goals

- Generate outbound paths and query parameters from the codecs in an inbound route declaration.
- Make the safe API the shortest and most discoverable path for links, server navigation, JS commands, and redirects.
- Preserve explicit escape hatches for external URLs, dead routes, and query-only patches.
- Keep encoding ergonomic in pure `render` methods while retaining a checked variant for intentionally partial codecs.
- Make location support a compile-time property of a route builder.
- Avoid adding a type parameter to `LiveView` or `RoutedLiveView`.

## Non-Goals

- A global reverse-route registry or generated route names.
- Typed query-only patches.
- Compile-time proof that a patch targets the currently mounted LiveView.
- Compile-time proof that navigation remains in the same live session.
- A safe abstraction for arbitrary external URLs or routes not declared through the Live DSL.
- Backward compatibility for the former raw-string method names. Scalive is in Alpha, so the safe API is the default.

## Route Builders As References

An immutable route-builder value serves two purposes:

1. It is mounted to a LiveView through the existing route DSL.
2. It constructs outbound `LiveLocation` values.

Applications can keep named route builders in a central object without introducing a registry:

```scala
object Routes:
  final case class UserLocation(id: Int, tab: Option[String])

  val user =
    (live / "users" / PathCodec.int("id"))
      .queryOptional[String]("tab")
      .mapParams { case (id, tab) => UserLocation(id, tab) }(
        location => location.id -> location.tab
      )

val appRoutes =
  Routes.user -> UserLiveView()
```

Changing the path or query declaration changes both inbound decoding and outbound encoding. Callers do not repeat path segments or query parameter names.

Path-only `LiveRouteSeed` and `LiveRouteBuilder` values construct locations from their path codec output. A `LiveRouteParamsBuilder` constructs locations from the final `Params` type delivered to `RoutedLiveView.handleParams`.

## Bidirectional Parameter Mapping

For `LiveRouteParamsBuilder[R, A, Need, Ctx, Params, Capability]`, the bidirectional mapping method has this compiled signature:

```scala
def mapParams[Params2](
  decodeParams: Params => Params2
)(
  encodeParams: Params2 => Params
)(using Capability =:= LiveRouteParamsCapability.Encodable
): LiveRouteParamsBuilder[
  R,
  A,
  Need,
  Ctx,
  Params2,
  LiveRouteParamsCapability.Encodable
]
```

`decodeParams` transforms inbound codec values into the application domain type. `encodeParams` reverses that transformation before the path and query codecs encode an outbound location.

The evidence parameter prevents applying a bidirectional mapping to a decode-only builder. The return type preserves the route environment, path, requirement, and context types, changes the final params type to `Params2`, and records the result as encodable.

The reverse function is total. An application whose domain type can contain values rejected by the underlying route codec should either make that state unrepresentable or use checked location construction.

## LiveLocation

`LiveLocation` is a nominal, immutable value representing a relative URL generated by an encodable route builder. Its constructor is not public.

```scala
final class LiveLocation private[scalive] (
  private[scalive] val url: URL
):
  def href: String
  def withFragment(fragment: String): LiveLocation
  def withFragmentEither(
    fragment: String
  ): Either[LiveLocation.EncodeError, LiveLocation]

object LiveLocation:
  enum EncodeError:
    case Path(details: String)
    case Query(cause: Throwable)
    case Fragment(details: String)

    def message: String

  final class EncodingException(val error: EncodeError)
      extends IllegalArgumentException(error.message)
```

`href` exposes the encoded relative URL for diagnostics and integration with APIs outside the navigation helpers. It does not permit constructing or changing a location. `withFragment` and `withFragmentEither` accept already percent-encoded URI-fragment syntax; they validate but do not encode decoded text. The caller must encode spaces, for example by passing `"profile%20details"` instead of `"profile details"`. Fragments do not participate in route matching. Like location construction, `withFragment` treats invalid fragment syntax as an invariant violation, while `withFragmentEither` exposes `EncodeError.Fragment` for checked handling.

Path-only `LiveRouteSeed[A]` values expose these compiled methods:

```scala
def location(value: A): LiveLocation
def locationEither(value: A): Either[LiveLocation.EncodeError, LiveLocation]
def location(using ev: A =:= Unit): LiveLocation
def locationEither(using ev: A =:= Unit): Either[LiveLocation.EncodeError, LiveLocation]
```

Path-only `LiveRouteBuilder[R, A, -Need, Ctx]` values expose the same path-value signatures:

```scala
def location(value: A): LiveLocation
def locationEither(value: A): Either[LiveLocation.EncodeError, LiveLocation]
def location(using ev: A =:= Unit): LiveLocation
def locationEither(using ev: A =:= Unit): Either[LiveLocation.EncodeError, LiveLocation]
```

`LiveRouteParamsBuilder[R, A, Need, Ctx, Params, Capability]` instead constructs locations from the final routed `Params` value and requires encodable capability evidence:

```scala
def location(
  params: Params
)(using Capability =:= LiveRouteParamsCapability.Encodable): LiveLocation

def locationEither(
  params: Params
)(using Capability =:= LiveRouteParamsCapability.Encodable
): Either[LiveLocation.EncodeError, LiveLocation]

def location(using
  Params =:= Unit,
  Capability =:= LiveRouteParamsCapability.Encodable
): LiveLocation

def locationEither(using
  Params =:= Unit,
  Capability =:= LiveRouteParamsCapability.Encodable
): Either[LiveLocation.EncodeError, LiveLocation]
```

The no-argument overloads are available only when the corresponding path or params type is `Unit`. The params-builder evidence also makes location construction unavailable on decode-only routes.

`location` delegates to `locationEither` and throws `LiveLocation.EncodingException` on failure. Encoding failure is treated as a route-codec or domain invariant violation, which keeps ordinary pure rendering direct:

```scala
link.navigate(
  Routes.user.location(UserLocation(user.id, None)),
  user.name
)
```

Code using deliberately partial `PathCodec` or `QueryCodec` transformations can call `locationEither` and handle `EncodeError` explicitly. Path encoding uses `PathCodec.encode`. Query encoding uses the original `QueryCodec` and catches only non-fatal encoder failures.

## Bidirectional And Decode-Only Codecs

`LiveParamsCodec` becomes a true codec. In addition to decoding the path parameters and URL, it encodes final parameters into the path value and query parameters needed to build a location.

Standard `.params`, `.query`, `.queryOptional`, and schema-derived query builders provide this encoder automatically. Query builders retain the `Combiner` needed to separate a final combined value during encoding.

Custom codecs provide both directions through `LiveParamsCodec.custom(decodeFn, encodeFn)`. The encoded representation contains:

- The path value consumed by the route's `PathCodec`.
- The `QueryParams` appended to that encoded path.

Some inbound parameter logic cannot be reversed because it inspects arbitrary URL state or deliberately projects away information. Those routes use explicit decode-only APIs:

```scala
builder.paramsDecodeOnly(decoder)
paramsBuilder.mapParamsDecodeOnly(decodeParams)
```

`LiveParamsDecoder` contains the reusable decode-only contract. `LiveParamsCodec` extends that contract with encoding.

Decode-only operations return a builder carrying `LiveRouteParamsCapability.DecodeOnly`. It can still be mounted to a `RoutedLiveView`, but `location` and `locationEither` require `LiveRouteParamsCapability.Encodable` and are therefore unavailable at compile time. The capability is the final type parameter of `LiveRouteParamsBuilder`; it does not affect `LiveView`, `RoutedLiveView`, or application model/message types.

This distinction avoids a runtime "encoder unavailable" error and makes irreversible routing explicit at its declaration.

## Safe Navigation APIs

Safe navigation methods retain the concise existing names and accept only `LiveLocation`.

### Links

```scala
link.navigate(to: LiveLocation, mods: Mod[Msg]*)
link.patch(to: LiveLocation, mods: Mod[Msg]*)
link.patchReplace(to: LiveLocation, mods: Mod[Msg]*)
```

### Lifecycle Contexts

```scala
ctx.nav.pushNavigate(to: LiveLocation)
ctx.nav.replaceNavigate(to: LiveLocation)
ctx.nav.pushPatch(to: LiveLocation)
ctx.nav.replacePatch(to: LiveLocation)
ctx.nav.redirect(to: LiveLocation)
```

`MountNavigation` continues to expose navigate and redirect operations but not patch operations. `Navigation` adds both patch variants as it does today.

### JS Commands

```scala
JS.navigate(to: LiveLocation, replace: Boolean = false)
JS.patch(to: LiveLocation, replace: Boolean = false)
```

### Mount Failures

```scala
LiveMountFailure.redirect(to: LiveLocation)
```

The compiled `LiveMountFailure` representation distinguishes the typed and unchecked cases:

```scala
enum LiveMountFailure:
  case Redirect(to: LiveLocation)
  case RedirectUnsafe(to: URL)
  case Unauthorized(reason: Option[String])
  case Stale(reason: Option[String])
```

All safe consumers serialize the already encoded location and reuse the current Phoenix link attributes, command JSON, navigation runtime, and protocol payloads. They perform no route lookup and cannot fail due to route encoding.

## Explicit Unsafe APIs

Unchecked destinations remain available, but their names make the loss of route safety visible:

```scala
link.navigateUnsafe(path: String, mods: Mod[Msg]*)
link.patchUnsafe(path: String, mods: Mod[Msg]*)
link.patchReplaceUnsafe(path: String, mods: Mod[Msg]*)

ctx.nav.pushNavigateUnsafe(to: String)
ctx.nav.replaceNavigateUnsafe(to: String)
ctx.nav.pushPatchUnsafe(to: String)
ctx.nav.replacePatchUnsafe(to: String)
ctx.nav.redirectUnsafe(to: String)

JS.navigateUnsafe(href: String, replace: Boolean = false)
JS.patchUnsafe(href: String, replace: Boolean = false)

LiveMountFailure.redirectUnsafe(to: URL)
```

These methods preserve valid Phoenix use cases that cannot be derived from a Live route declaration:

- Navigating to an external or dead route.
- Redirecting to an arbitrary parsed URL during a mount aspect.
- Query-only patches such as `"?page=2"`, which retain the current path.
- Compatibility fixtures that intentionally exercise raw URL behavior.

There is no implicit conversion from `String` or `URL` to `LiveLocation`.

## Data Flow

Typed outbound navigation follows a short, local path:

1. The route builder receives the final typed parameter value.
2. A bidirectional parameter mapping reverses the domain projection, if present.
3. The params codec separates path and query values.
4. The original `PathCodec` encodes the path.
5. The original `QueryCodec` encodes query parameters.
6. The builder combines both into a relative URL and wraps it in `LiveLocation`.
7. Link, context, JS, or redirect APIs serialize the location through their existing runtime behavior.

No global route table is consulted during encoding. A named builder can be reused for many locations, and a constructed `LiveLocation` can be reused by many consumers.

## Error Semantics

- `EncodeError.Path` preserves the failure details returned by `PathCodec.encode`.
- `EncodeError.Query` preserves the non-fatal cause thrown by query encoding.
- `EncodeError.Fragment` preserves the failure details returned while parsing a fragment.
- `locationEither` returns these errors without modification.
- `location` and `withFragment` convert a reported `EncodeError` to `EncodingException`; this exception is reserved for route-codec or domain invariant violations.
- `withFragmentEither` returns fragment errors without modification.
- Errors do not include the encoded parameter value by default, avoiding accidental disclosure of application data.
- Unsafe APIs retain their current downstream URL parsing and runtime behavior.

The checked API is intended for genuinely partial custom codecs. Ordinary route codecs and total domain mappings should use `location`; a failure there indicates an invalid route-codec invariant rather than expected user-input validation.

## Migration

This is intentionally a breaking Alpha API improvement:

- Replace one-way `mapParams(f)` calls with `mapParams(decode)(encode)` where outbound construction is possible.
- Replace irreversible mappings and custom codecs with `mapParamsDecodeOnly` or `paramsDecodeOnly`.
- Give routes used by outbound navigation stable application-level values such as `Routes.user`.
- Replace internal raw paths with locations generated from those named builders.
- Rename unavoidable raw-string navigation calls to their explicit unsafe forms.
- Update mount-failure redirects to distinguish typed and unchecked destinations.

The beginner example should demonstrate named builders and typed links. E2E fixtures should use typed locations when they target declared routes, while fixture-specific external, dead-route, and query-only behavior should remain explicit through unsafe methods.

## Testing

### Route Encoding

Add focused tests for:

- Static and `Unit` routes.
- Dynamic paths.
- Required and optional query parameters.
- Omission of absent optional query parameters.
- Bidirectionally mapped domain parameters.
- Correct path, query, and fragment percent encoding.
- Reuse of one route builder for inbound matching and outbound construction.
- `locationEither` path and query failures.
- `withFragmentEither` fragment failures.
- `location` and `withFragment` wrapping failures in `EncodingException`.

### Compile-Time Capabilities

Add type-safety tests proving:

- Encodable builders expose `location` and `locationEither` with the final parameter type.
- Decode-only builders can still be mounted.
- Decode-only builders do not expose location construction.
- A location for one route can be consumed by all safe navigation APIs without exposing its underlying builder type.
- Raw `String` and `URL` values are not accepted by safe methods.

### Navigation Consumers

Add focused tests for:

- Typed link `href` and Phoenix navigation attributes.
- Typed JS navigate and patch JSON.
- Typed push/replace navigate, push/replace patch, and redirect commands.
- Typed and unchecked mount-failure redirects.
- Replace behavior remaining unchanged.
- Query-only patch behavior remaining available through unsafe APIs.

Run the existing lifecycle, component, async, flash, layout, socket, and upstream navigation suites to verify that protocol and browser behavior remain unchanged.

## Success Criteria

- A path or query refactor in a named route builder automatically changes its outbound locations.
- Application code can use the same `LiveLocation` with links, lifecycle navigation, JS commands, and redirects.
- Common location construction is direct and pure; checked construction preserves codec failures when needed.
- Irreversible route declarations cannot construct locations at compile time.
- Raw strings are accepted only by explicitly unsafe navigation methods.
- Existing runtime payloads and browser navigation behavior remain unchanged.
- Focused native tests and the existing upstream navigation suite pass.
